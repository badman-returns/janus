# Mission control v0.5 — the cockpit

**Status:** shipped 0.5.0–0.5.4 on 2026-09-02. Deviations from the text below, all deliberate:
- §1 no ttyd basic auth (Chrome blocks auth prompts in iframes); localhost bind hard-coded. `ttyd-run.sh` watchdog added: ttyd 1.7.7 on macOS leaks a pty master per closed client.
- §3 the icon rail became a full **sidebar** (Overview / Sessions / Services / Machine / System; hover-expand, pinnable) and replaced the tile tray entirely — the tray was a list of everything competing with the content.
- §4 plus: the watcher now types the pickup prompt into a live session inside the machine; the "dropped" Stop-hook drain was not needed.
- Boot at login (`install-login.sh`) added; needs Full Disk Access for `/bin/bash` when the plugin lives under `~/Documents`.
**Problem:** the dashboard is a file reader. Claude's real I/O (what it prints, what it asks, what the operator types) never touches a file, so the web shows machine *state* but cannot be used to *work*. The operator built it to stop living in the terminal; today it forces him back there for every interaction.
**Goal:** web is the one place. Viewing and interacting are the same surface: interactive things (Claude sessions, service shells) are real terminals inside the page; the machine's state (gates, proof, runs, agents) wraps around them.

## Non-goals

- A chat UI over the Agent SDK. The Claude Code TUI is the interaction; we embed it, we do not replace it.
- Claude Code Remote Control and the voice concierge. Later, separately.
- Exposing anything beyond localhost. Remote access is Tailscale only, a later step.

Dropped on purpose: a transcript/conversation feed (#1 — the terminal is the feed); Stop-hook inbox injection (#3 — with a live terminal the operator types into Claude directly; Claude Code queues input mid-turn. Notes remain the channel for the no-session/headless path).

## 1. Real terminals in the browser

**Runtime:** `ttyd` (brew, 1.7.7, single binary, bundles xterm.js + websocket). Keeps `server.js` zero-dependency. One `ttyd` per machine, started by the orchestrator in its own tmux window, **bound to `127.0.0.1`** (hard-coded, not configurable), port from the fleet registry (`ttyd_port`, first free in 5600–5699).

**Per-tile attach — `scripts/dm-attach.sh <window>`.** ttyd runs with `-a` (URL args) and command `dm-attach.sh`; the tile iframes `http://127.0.0.1:<ttyd_port>/?arg=<window>`. The script creates a **grouped tmux session** so every browser tile has its own current window and does not fight other tabs or the operator's own attach:

```bash
tmux new-session -t "dm-$PROJ" -s "view-$$-$RANDOM" \; set destroy-unattached on \; select-window -t "$1"
```

Panes are shared (same processes, same scrollback), only the *view* is per-client. Closing the tile kills the grouped session. If the window does not exist the script prints one line and exits, which the iframe shows.

**Tiles.** Every tmux window keeps its tile ("terminal · api"); the body becomes the iframe. The 2.6s `capture-pane` poll stays only as the **fallback** when `ttyd` is not installed: read-only snapshot plus a one-line banner `brew install ttyd — then restart the machine — for a live terminal`. Detection: `command -v ttyd` in the orchestrator, recorded in the registry as `ttyd_port: null`.

**Terminal theming.** xterm inside the iframe is themed from the same tokens as the page via ttyd client options (`-t fontFamily`, `-t fontSize`, `-t theme=<json>`), generated by the orchestrator from a small `theme.json` in `mission-control/`. Light and dark both. A terminal that does not match the page is the single most visible way this reads as "old school"; this is a requirement, not polish.

**Security.** A terminal in a browser is a shell. Localhost bind is hard-coded; ttyd basic auth (`-c`) from `config.json` (`ttyd_auth: "user:pass"`, generated by `dm-init` if absent). The dashboard itself stays unauthenticated on localhost as today. Remote = Tailscale serve of the dashboard port only, later; the ttyd port is never exposed directly.

## 2. Claude runs inside the machine

The session must be a tmux window to have a tile.

- **`scripts/dm.sh` launcher** (from project root): ensures the machine is up (orchestrator), creates window `claude` running `CLAUDE_CONFIG_DIR=<config.claude_config_dir or unset> claude "$@"` (so `dm.sh --resume <id>` works), attaches the operator's terminal to it. Replaces `cd project && claude`.
- **"+ session" button** on the dashboard: `POST /api/service {window:"claude-N", action:"start"}` with a reserved service name `claude` in config (`dm-init` writes it: `"claude": "claude"`). Windows `claude`, `claude-2`, `claude-3`… Multiple orchestrators side by side, from the browser.
- `session-start.sh` checks `$TMUX` and the session name; when Claude is running outside `dm-*`, it injects one warning line: `this session is invisible to mission control — start it with dm.sh`.

Subagents are in-process; they never get a terminal. Their visibility is the **agents / activity** tiles (hook-driven, correct since 0.4.2). Services they start go through `dm-run.sh` → tmux window → a live terminal tile appears with no further code.

## 3. Layout for working, not glancing

- **Focus mode**: any terminal tile expands to full width; other tiles collapse to a left rail of icons+counts (alerts still visible). `Esc` / click rail to return. Command palette gains `focus <window>`.
- **Split**: two terminals side by side (e.g. `claude` + `api`), drag divider. Persisted in `localStorage` with the existing layout state.
- **Mobile** (< 720px): one terminal at a time, a horizontal window switcher above it, cards below. The soft keyboard works for typing; arrow-heavy TUI navigation is what the question cards (§5) exist for.
- Every non-terminal tile is unchanged in data, restyled per §6.

## 4. Liveness fix (bug — ships first)

`watch.sh` and the agents tile both use `.delivery/agents/*.json` heartbeats: a session is live if any heartbeat is younger than 120s. `runs.jsonl` is no longer consulted for liveness. The watcher also skips dispatch when a `claude*` tmux window exists in the machine (a session is open even if idle). Removes the double-orchestrator race.

## 5. Question and permission cards

Two hooks, added to `hooks.json`:

- `PreToolUse` matcher `AskUserQuestion` → `scripts/ask.sh`: writes `.delivery/inbox/ask-<ts>-<slug>.txt` with the question and its options (JSON body), pushes `notify.sh "QUESTION: <headline>"`, then **waits** (poll 2s, hook `timeout: 600`) for `reply-*` answering it. On reply: returns `{"hookSpecificOutput":{"permissionDecision":"deny","permissionDecisionReason":"Operator answered from mission control: <answer>"}}` so Claude receives the answer without the TUI prompt. On timeout: exits 0 (the TUI prompt shows as normal; the card stays and is dismissed when the session answers it in the terminal — `Stop` hook clears stale `ask-*` older than the session's last prompt).
- `Notification` matcher `permission_prompt` → same script, `permission` mode: card with **Allow / Deny**, push. `PermissionRequest` hook returns the decision when a reply arrives; timeout → normal TUI prompt.

Dashboard: `ask-*` files render in **Waiting on you** as a card with the options as buttons (single or multi-select per the tool input) and a free-text field; replying posts `reply-<ts>-<stem>.txt` as today. Gate cards (`gate-*`) unchanged.

`ntfy_topic` is set during this slice; `notify.sh` unchanged.

## 6. Visual direction — "instrument panel"

The user's bar: outstanding, aligned, clean, not old-school. Concretely:

- **One type system.** Keep Geist / Geist Mono (already loaded) and enforce a scale: 11 / 12.5 / 13.5 / 16 / 22px, mono only for identifiers, counts, timestamps, terminal. No third family. Terminal font = the page mono at the same size, so the iframe reads as part of the page, not a widget.
- **Palette from tokens, both themes.** Existing near-black + lime accent stays as the base; every color in `index.html`, `fleet.html`, and the ttyd theme comes from the same token file. Light theme gets the same care as dark (today it is an afterthought). Alert state = one warm accent, used only for "needs you".
- **Density with hierarchy.** Terminal tiles are the heaviest element; state tiles are quiet, uniform, and never louder than a terminal. Card headers lose the uppercase-tracked "dashboard" look in favor of weight and size. Counts and statuses are pills, one style.
- **Motion only for state change**: a card arriving, a terminal focusing. No decorative animation, no glow gradients.
- **Designed empty and waiting states**: empty is a single quiet line; waiting is the one place the accent appears.
- **No iframe seams**: no borders around terminals, page background continues into xterm's background, scrollbars styled to the theme.
- `fleet.html` restyled to the same system; it is the home screen.

The `frontend-design` skill is loaded at implementation time for §3 and §6; the spec fixes the direction, not the pixels.

## Testing

- `dm-attach.sh`: two tiles for different windows open at once; switching one does not move the other; closing a tile leaves no `view-*` session (`tmux ls`).
- ttyd absent: tile shows the snapshot + banner; machine otherwise unaffected.
- Liveness: live idle session for 3 minutes with a note in the inbox → watcher does not dispatch; kill the session → dispatch within one poll.
- Ask card: `AskUserQuestion` in a session → card + push within 2s; answer on the web → Claude proceeds with that answer, no TUI prompt; no answer for 10 min → TUI prompt appears, card clears after it is answered.
- Theme: screenshot light and dark with a focused terminal; page and xterm backgrounds identical by pixel.
- Proof folder `proof/cockpit/` per the machine's own rule.
